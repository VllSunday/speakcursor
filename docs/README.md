## Порядок работы

1. Согласовать состав функций первой версии — выполнено, детали ещё обсуждаются.
2. По порядку разобрать сценарии, необходимые экраны, действия и состояния.
3. Подготовить визуальные макеты под согласованные сценарии.
4. Дополнить каждую спецификацию поведением при ошибках и критериями приёмки.
5. Выбрать стек с учётом функций, интерфейса и платформ.
6. Реализовывать и тестировать по этапам.

Текущий этап: третий пункт — облачная обработка и подключения. Для первой версии выбран только OpenAI. Обсуждение приостановлено по просьбе пользователя до следующего продолжения. Записи ведутся сразу; полные спецификации для реализации появятся после согласования UX и макетов.

## Где продолжить

1. Открыть [облачную обработку](features/03-cloud-processing.md).
2. Продолжить с настроек ключа OpenAI и назначения моделей по функциям. Решение о провайдере уже принято и повторного вопроса не требует.
3. После этого вернуться к оставшимся пунктам списка по порядку. Основные решения по локальной диктовке и обработке новой речи уже записаны; визуальные детали и оставшиеся вопросы отмечены в соответствующих файлах.

На момент паузы сохранены документация и исследовательские материалы. Стек новой версии не выбран, её реализация не начата. Для продолжения с другого аккаунта используйте [передачу контекста](handoff.md).

## Как читать документы

- «Согласовано» — пользователь явно включил возможность или установил ограничение.
- «Предложение» — вариант для обсуждения, ещё не утверждённый пользователем.
- «Открытый вопрос» — решение пока не принято.
- Описание существующего кода не означает, что его поведение утверждено для нового интерфейса.

После ответа пользователя нужно обновить соответствующий документ, затем переходить к следующему вопросу. Не превращать предложения в требования без ответа. Не начинать реализацию или выбирать стек до соответствующего этапа.
