## Порядок работы

1. Согласовать состав функций первой версии — выполнено, детали ещё обсуждаются.
2. По порядку разобрать сценарии, необходимые экраны, действия и состояния.
3. Подготовить визуальные макеты под согласованные сценарии.
4. Дополнить каждую спецификацию поведением при ошибках и критериями приёмки.
5. Выбрать стек с учётом функций, интерфейса и платформ.
6. Реализовывать и тестировать по этапам.

Текущий этап: базовые сценарии первой версии согласованы, включая подготовку промпта только из речи; прикрепление изображения к ней отложено. Краткая [сводка первой версии](mvp.md) отделяет принятое поведение от деталей, которые можно уточнять при реализации. Для новой версии выбраны Rust и Slint; собран прототип двух панелей и начато независимое от ОС ядро диктовки. Дальше нужно проверить окна на Windows и выбрать остальные компоненты стека.

## Где продолжить

1. Сверить [сводку первой версии](mvp.md) с принятыми решениями.
2. Проверить прототип Slint на Windows и выбрать остальные компоненты Rust-стека.
3. Дополнить минимальные макеты основных поверхностей и вести реализацию по этапам; тонкие состояния уточнять по мере необходимости.

## Как читать документы

- «Согласовано» — пользователь явно включил возможность или установил ограничение.
- «Предложение» — вариант для обсуждения, ещё не утверждённый пользователем.
- «Открытый вопрос» — решение пока не принято.
- Описание существующего кода не означает, что его поведение утверждено для нового интерфейса.

После ответа пользователя нужно обновить соответствующий документ, затем переходить к следующему вопросу. Не превращать предложения в требования без ответа.
