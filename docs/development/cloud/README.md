# Состояние облачной среды при подготовке проекта

Это запись проверок существующего Windows-приложения в облачной Linux-среде 15 октября 2026 года. Она сохраняет контекст подготовки, а не выбирает стек новой кроссплатформенной версии.

## Проверенная среда

- Debian 13, Linux x86_64, Python 3.12.
- Отдельная `.venv` в checkout; системные Python-пакеты не менялись.
- CPU-зависимости из исходного `requirements.txt` без двух необязательных CUDA-пакетов NVIDIA.
- `faster-whisper==1.2.1`, `av==16.1.0`: PyAV 19 ломал чтение аудио из-за отсутствия аргумента `metadata_errors`; отдельный constraint исправил несовместимость.
- PortAudio получен через подписанные метаданные Debian и распакован в локальный sysroot вне checkout.
- Для проверки Qt использовался offscreen-режим, для данных приложения — отдельный APPDATA.
- Установленные версии: [installed-versions.txt](installed-versions.txt). Это наблюдение о среде, не новый lockfile приложения.

## Что прошло

- `pip check`.
- Создание диалога настроек и отрисовка трёх состояний иконки Qt без экрана.
- Декодирование `assets/demo.mp4`.
- Реальная ONNX-проверка речи на публичном JFK-фрагменте из репозитория OpenAI Whisper и отсутствие речи на тишине.
- Сохранение/загрузка истории и ограничение 20 записей.
- Возврат текста без обращения к GPT при отсутствии ключа.
- Загрузка библиотеки PortAudio.

## Ограничения и незавершённые проверки

- Полный запуск `main.py` в Linux останавливается на Windows API `ctypes.windll.user32` в `clipboard.py`.
- Физического микрофона, графического рабочего стола и GPU в проверенной среде не было.
- Загрузка Whisper-модели с Hugging Face получила сетевой отказ 403. Полная транскрипция моделью не проверялась; VAD не заменяет эту проверку.
- CUDA, Windows hotkeys/paste/autostart и реальные запросы OpenAI не проверялись.
- В прежнем аккаунте сохранён черновик `install_script`, `start_skill` и сетевые домены `huggingface.co`, `cas-bridge.xethub.hf.co`. Публикация среды не подтверждалась. Настройки аккаунта и черновик не переносятся через Git.

## Сохранённые шаги подготовки

[install-tested.sh](install-tested.sh) — точное содержимое установочного скрипта, который выполнялся и повторно прошёл проверки на той машине. Он создаёт окружение, constraints, локальную библиотеку, переменные и smoke-helper.

Скрипт исторически рассчитан на checkout `/workspace/speakcursor` и вспомогательную директорию `/workspace/speakcursor-env` в Debian x86_64. Если пути или платформа другие, перед выполнением нужна адаптация. Для обычного Windows-запуска используйте основной README проекта.

После выполнения скрипта в соответствующей среде:

```bash
cd /workspace/speakcursor
source /workspace/speakcursor-env/env.sh
python -m pip check
python -c 'exec(compile(open("/workspace/speakcursor-env/smoke.py").read(), "/workspace/speakcursor-env/smoke.py", "exec"))'
```

Живые процессы не считаются сохранёнными между задачами. Для headless-проверок постоянный сервис не нужен. Каждая облачная задача изолирована; используйте существующий checkout, не создавайте worktree без прямого запроса пользователя.

В Git сохраняются команды и результаты проверок. `.venv`, кэши пакетов, модельные веса, файлы с пользовательскими ключами и локальные настройки приложения не включаются.

## Прототип Rust/Slint, 17 октября 2026 года

После выбора Rust и Slint для новой версии добавлен отдельный [прототип двух панелей](../../../prototypes/slint-panels/README.md). Для его проверки в этой Debian-среде Rust 1.99.1 и Cargo установлены через официальный rustup во временные каталоги `/tmp/speakcursor-rustup` и `/tmp/speakcursor-cargo`; Windows GNU target добавлен для проверки Windows-ветки кода. Проект использует Slint 1.18.1 и собственный `Cargo.lock`.

Исходный образ содержит библиотеку Fontconfig, но не её файл `pkg-config` для сборки Rust-зависимости. Официальный пакет Debian `libfontconfig-dev` версии 2.15.0-2.3, совпадающей с установленной библиотекой, скачан и распакован в локальный sysroot. Пакет не устанавливался в системные каталоги. Подготовленные Rust, Cargo, CMake и sysroot скопированы в `/workspace/speakcursor-env/rust-dev`; для повторной сборки в **этой уже подготовленной среде**:

```bash
source /workspace/speakcursor-env/rust-dev/env.sh
cargo check --manifest-path prototypes/slint-panels/Cargo.toml --locked --offline
```

Та же проверка с `--target x86_64-pc-windows-gnu` прошла, а обычный `cargo build --locked` собрал исполняемый файл Linux. `cargo fmt --check` также прошёл. Windows target проверяет типы и зависимости Windows-ветки, а не запускает приложение на Windows и не подтверждает поведение фокуса. В среде нет графического рабочего стола и физического Windows-окна; порядок реальной проверки описан в README прототипа. В обычной Debian-среде вместо временного sysroot можно установить системный `libfontconfig-dev` и использовать стандартный `cargo`.

При развитии первого блока CTranslate2 занимает несколько гигабайт во время сборки. Несколько отдельных `CARGO_TARGET_DIR` заполнили небольшой `/tmp` и сборка остановилась на архивировании C++, хотя Rust-код не был причиной сбоя. Для следующих проверок используйте один каталог сборки на более ёмком диске, например `/workspace/.speakcursor-target` вне checkout, и не создавайте новый target для каждого crate. После переноса каталога CMake пришлось очистить только пакет `ct2rs` командой `cargo clean --manifest-path crates/speakcursor-dictation/Cargo.toml -p ct2rs`, поскольку его кэш содержал старые абсолютные пути. После этого тесты пайплайна диктовки прошли. Linux-проверка интерфейса не доказывает работу микрофона, окон и вставки Windows; для этого в репозитории есть Windows CI и запланирована одна пользовательская проверка полного первого блока.

Для текущей проверки Windows-кода из Linux использован Zig как C/C++ компилятор. При сборке `windows-sys` дополнительно нужен `x86_64-w64-mingw32-dlltool`; локальный wrapper вызывает `zig dlltool`. `cargo check --target x86_64-pc-windows-gnu --tests` проверяет код, но `cargo test --no-run` с этим Zig linker останавливается на несовместимом аргументе GNU линкера. Исполняемые Windows-тесты и релизную сборку поэтому запускает нативный GitHub Actions runner; результат Linux cross-check нельзя считать успешной линковкой Windows-приложения.
