# Локальная диктовка

Статус: основные сценарии согласованы. Детали отображения и настройки будут уточняться при проектировании интерфейса; независимая от ОС логика управления записью начата в Rust, захват звука и распознавание ещё не реализованы.

## Согласовано

- Пользователь может выбрать распознавание локальной моделью или через API. Локальный вариант остаётся доступен без облака; API-вариант входит уже в первый крупный блок.
- Для первой крупной проверки локальный движок должен принимать формат CTranslate2 из прежней версии (`faster-whisper`, модель по умолчанию `large-v3`); другие форматы можно добавить позже. Фактический выбор модели на машине пользователя неизвестен, поскольку локальный файл настроек не хранится в репозитории.
- Пользователь может выбрать Whisper-модель и язык.
- Нужны CPU и доступное GPU-ускорение.
- Сохраняется возможность выгрузить модель в простое.
- Выбранная модель загружается в память при запуске приложения после первоначального подключения.
- Время простоя до выгрузки модели изменяется в настройках.
- Для первой версии это единственный тип встроенных локальных моделей.
- Облачная редактура распознанного текста — отдельный этап, который можно отключить.
- Пользователь самостоятельно выбирает модель. Мастера первого запуска и автоматических рекомендаций нет.
- Уже скачанная локальная модель подключается через системный диалог выбора.
- Можно добавить несколько локальных моделей. Список сохраняется между запусками; активная модель выбирается из списка без повторного поиска в файловой системе.
- Одновременно для диктовки выбрана одна активная модель. Сам список не означает одновременной загрузки всех моделей.
- Обычная диктовка не требует удерживать клавишу: первое нажатие назначенного сочетания начинает запись, второе завершает её и запускает распознавание и выбранную обработку.
- Завершающее нажатие должно быть повтором именно того сочетания, которым начался сеанс. Другое сочетание, даже если оно выбирает тот же стиль, не завершает запись.
- Esc во время обычной записи отменяет её без распознавания и вставки текста.

## Что уже есть в коде

- [whisper_service.py](../../whisper_service.py): загрузка модели, попытка CUDA при наличии, CPU fallback с int8, выгрузка и распознавание.
- [settings.py](../../settings.py): модель, язык и настройка выгрузки.
- [tray.py](../../tray.py): текущий выбор модели в настройках трея.
- [main.py](../../main.py): предварительная загрузка и проверка простоя.

Текущая реализация ориентирована на Windows. Её наличие не доказывает поддержку GPU на каждой будущей целевой ОС.

## Выбор модели: принятое решение

- Приложение должно оставаться минималистичным: пользователь открывает настройки и самостоятельно выбирает нужное.
- Предложение мастера с рекомендацией модели отклонено.
- Нужен простой способ указать уже существующую локальную модель.
- Каталог допустим как способ выбора, если он потребуется; обязательный встроенный каталог и скачивание из него пока не утверждены.
- Формат модели и выбор файла либо папки уточняются при проектировании технической поддержки. Требование относится к простоте подключения, а не к обещанию поддержки любого файла модели.

## Список моделей: принятое решение

- Пользователь согласовал сохраняемый список добавленных локальных моделей.
- Модель добавляется один раз, после чего её можно выбрать в списке.
- Альтернатива с хранением только единственной заменяемой модели не выбрана.
- Этот список относится к локальной диктовке. Каталог API-моделей получает данные от выбранного сервиса и описан отдельно в составе продукта.

## Отказ GPU и переход на CPU: принятое решение

- Если запуск на GPU не получился, показать причину и предложить запуск на CPU.
- Запуск на CPU выполняется только после явного согласия пользователя.
- Автоматически и без подтверждения переключаться с выбранного GPU на CPU нельзя.
- Сохранять ли этот выбор между сессиями и повторно ли спрашивать при следующем отказе GPU, ещё не определено.

Существующий код использует автоматический fallback; при будущей реализации его поведение нужно привести к согласованному сценарию. Код сейчас не меняется.

## Загрузка и выгрузка: принятое решение

- Загружать выбранную модель при запуске приложения.
- Выгружать модель из памяти после простоя в соответствии с настройкой пользователя.
- Пользователь может изменить время до выгрузки в настройках.
- После выгрузки следующая диктовка сразу начинает запись и параллельно подготавливает выбранную модель.
- Если запись завершилась до готовности модели, она дожидается распознавания; пользователю не требуется повторять речь.
- Конкретное отображение состояния подготовки ещё нужно спроектировать.

## Управление записью: принятое решение

- Первое нажатие сочетания диктовки начинает запись; второе заканчивает её.
- Завершённая запись проходит выбранный способ распознавания, затем выбранный режим обработки и согласованный сценарий вставки.
- Esc до второго нажатия отменяет сеанс без распознавания и вставки. Это отдельный сеанс от помощи по экрану, хотя управление записью похоже.
