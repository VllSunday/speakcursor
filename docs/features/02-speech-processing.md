# Обработка новой речи

Статус: согласованы базовые режимы, горячие клавиши, автовставка успешной диктовки и выбор действий с копированием распознанного текста в буфер при ошибке облачной обработки. Остальные детали уточняются отдельно.

## Согласовано

- Сохранить и доработать обычную редактуру и структурирование надиктованных мыслей.
- Распознавание речи выполняется локальной моделью; последующая редактура — через API.
- Облачную обработку можно отключить.
- Подключение и модель для задачи выбирает пользователь.
- Переключение должно быть удобным в новом интерфейсе.
- Подготовка промптов — самостоятельная функция, а не только обработка изображений или другое название структурирования.
- Пользовательские стили и правила предусмотрены отдельным блоком персонализации.
- Для каждого из трёх готовых режимов и одного пользовательского стиля можно назначить отдельную клавишу или сочетание клавиш.
- Назначенное сочетание запускает диктовку в соответствующем режиме; предварительно переключать режим в настройках не требуется.
- Есть общая настраиваемая клавиша/комбинация диктовки, которая использует выбранный пользователем режим по умолчанию.
- Пользователю не требуется назначать все три отдельных сочетания: можно пользоваться только общим вызовом и одним выбранным режимом.
- Активная запись завершается повтором того же сочетания, которым она запущена. Другое сочетание, назначенное тому же стилю, не считается завершающим нажатием.
- Во время диктовки внизу показывается компактная плашка с волнами, отражающими речь.
- Пользователь выбирает режим обработки по умолчанию для общего вызова; дополнительное сочетание сразу запускает назначенный ему режим или стиль. Пробел и пробел с F1 — примеры, не утверждённые значения клавиш.
- Подготовка промпта вызывается отдельно и преобразует надиктованную задачу в промпт; детали — в [подготовке промптов](08-prompt-generation.md).

## Существующая основа

[gpt_formatter.py](../../gpt_formatter.py) содержит два промпта: обычная редактура и структурирование в Markdown. При отсутствии ключа или ошибке API текущий код возвращает исходный распознанный текст. Наличие этого поведения в коде не утверждает все детали обработки ошибок новой версии.

## Базовые режимы: принятое решение

Пользователь подтвердил следующий набор:

| Режим | Ожидаемый результат |
| --- | --- |
| Без обработки | Текст распознавания без дополнительной LLM-редактуры |
| Исправление | Исправить пунктуацию и ошибки в словах без переформулирования |
| Структурирование | Оформить надиктованное как пригодный для работы текст, например ТЗ или README, сохранив факты |
| Пользовательский стиль | Обработать расшифровку по сохранённому пользователем промпту |

Режим «Без обработки» не обещает буквальную передачу всех звуков речи: сам распознаватель может нормализовать текст.

Три готовых режима и один пользовательский стиль утверждены. Точные подписи в интерфейсе ещё нужно спроектировать. Пользовательский промпт сохраняется и может быть выбран режимом общего вызова диктовки.

## Горячие клавиши: принятое решение

Отдельно настраиваются вызовы:

- диктовки без дополнительной обработки;
- диктовки с исправлением пунктуации и ошибок;
- диктовки со структурированием.
- диктовки с пользовательским стилем.

Можно назначать одиночную клавишу или сочетание. Конкретные значения по умолчанию пока не выбраны. Вызов подготовки промптов остаётся отдельным сценарием.

Дополнительно согласован общий вызов диктовки:

- общая клавиша использует сохранённый режим по умолчанию;
- отдельная клавиша режима запускает именно этот режим;
- все параметры пользователь настраивает самостоятельно.

Пробел упоминался пользователем как пример, а не как утверждённая глобальная клавиша по умолчанию. Конкретную клавишу и её совместимость с обычным вводом ещё нужно определить. «Предустановленный режим» здесь относится к настройкам приложения, а не к настройкам диктовки операционной системы.

## Уточнение общего вызова

Диктовка и команды к выделению вызываются раздельно. В режиме диктовки речь вставляется как новый текст или заменяет выделение; само наличие выделения не превращает её в команду. Для редактирования или анализа текста используется отдельный вызов, описанный в [редакторе выделения](06-selection-editor.md). Дополнительные сочетания режимов и стилей остаются необязательными. Пример стиля с исправлением пунктуации не меняет ранее согласованный исходный режим «Без обработки»; пробел остаётся примером клавиши.

## Предустановленный режим: принятое решение

- Пока пользователь не выбрал другой вариант, применяется режим «Без обработки».
- Для этого режима не требуется API-ключ: результат локального распознавания используется без дополнительной LLM-редактуры.
- Пользователь может выбрать исправление, структурирование или пользовательский стиль своим режимом по умолчанию.

## Результат новой диктовки: принятое решение

- После успешного распознавания и выбранной обработки сразу вставлять новую диктовку в исходное активное поле.
- Предварительное подтверждение каждой вставки не требуется.
- Правило действует для успешной диктовки во всех четырёх вариантах. При ошибке облачной обработки применяется отдельный сценарий ниже.
- Сохраняется история результатов.

Ответ на вопрос/запрос ассистенту в другое приложение не вставляется: он показывается в верхней панели как аккуратно оформленный текст, который можно скопировать. Это отдельный сценарий от диктовки.

Для редактора выделения согласованы предпросмотр и немедленное копирование результата в буфер с применением через Ctrl+V или кнопку вставки. Для подготовки промпта отдельно согласована немедленная вставка готового результата в исходное поле без предпросмотра. Результаты редактора выделения по-прежнему применяются вручную.

## Ошибка облачной обработки диктовки: принятое решение

Если локальное распознавание завершилось, а облачное исправление, структурирование или пользовательский стиль завершились ошибкой:

- Сохранить распознанный текст и сразу скопировать его в системный буфер обмена.
- Показать в верхней панели ошибку и выбор: «Повторить обработку» или «Вставить без обработки».
- Пользователь может сразу вставить распознанный текст обычным сочетанием вставки (например, Ctrl+V), без повторного обращения к LLM и без нажатия кнопки в панели.
- Автоматической вставки в поле при этой ошибке нет; вставка выполняется по действию пользователя.
- Для этого сценария не восстанавливать прежнее содержимое буфера автоматически: распознанный текст должен оставаться доступным для ручной вставки. Это исключение из общего поведения восстановления буфера при обычной автовставке.

После успешного повтора облачной обработки диктовки сразу вставлять обработанный текст в исходное поле, без дополнительного предпросмотра или подтверждения. Поведение при недоступности исходного поля, ошибки копирования в буфер и закрытие панели предстоит уточнить отдельно.
