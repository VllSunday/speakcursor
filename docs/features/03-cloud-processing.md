# Облачная обработка и подключения

Статус: согласованы OpenAI как единственный провайдер первой версии, один общий ключ и отдельный выбор модели для каждой задачи, включая облачное распознавание речи. Проверка подключения и загрузка каталога запускаются автоматически при сохранении ключа. Модели назначаются задачам в едином разделе «Модели». При ошибке облачной обработки диктовки показывается выбор, а распознанный текст сразу копируется в буфер. Ключ сохраняется между запусками в защищённом хранилище ОС. Конкретный механизм по платформам, состояния проверки и остальные ошибки ещё предстоит уточнить.

## Согласовано

- Пользователь подключает OpenAI одним собственным API-ключом, общим для всех облачных функций. Отдельные ключи по функциям в первой версии не нужны.
- В первой версии поддерживается только OpenAI. Anthropic и другие провайдеры, в том числе сторонние OpenAI-совместимые сервисы, остаются на будущее.
- Модель выбирается отдельно для каждой задачи. Одна и та же совместимая модель может использоваться в нескольких задачах; общий ключ не означает общую модель.
- При сохранении введённого или изменённого ключа приложение автоматически проверяет подключение и загружает каталог моделей. Отдельное нажатие кнопки проверки для этого не требуется.
- После ввода ключа нужен список доступных моделей с фильтрацией по типу задачи.
- Назначения API-моделей собраны в едином разделе «Модели»: список задач и выбор подходящей модели напротив каждой.
- Каталог обновляется при открытии раздела «Модели»; также доступна кнопка «Обновить список». Обновление сохраняет назначенные пользователем модели.
- Облачную редактуру диктовки можно отключить; исходный режим — без дополнительной обработки.
- Локальные LLM и локальный анализ изображений в первую версию не входят.
- Редактура, структурирование, работа с выделением и промптами, анализ экрана и ассистент используют соответствующие API-возможности.
- Голосовой ответ требует синтеза речи, поиск в интернете — поискового инструмента или поддержки со стороны сервиса.
- Настройки минималистичны; автоматические рекомендации и мастер настройки не нужны.

Сценарий каталога и ограничения метаданных описаны в [составе продукта](../product-scope.md).

## Провайдер первой версии: принятое решение

- Пользователь выбрал только OpenAI и попросил закончить обсуждение на этом решении.
- Универсальный выбор произвольного провайдера или стороннего OpenAI-совместимого сервиса не входит в согласованный объём первого выпуска.
- Ранее названные Anthropic и другие варианты не являются требованиями первой версии.

Поддержка конкретных возможностей OpenAI должна проверяться по выбранной модели: текст, входные изображения, синтез речи и инструменты не считаются автоматически доступными у каждой модели.

## Хранение ключа: принятое решение

- Ключ OpenAI сохраняется между запусками в защищённом хранилище операционной системы; повторный ввод при каждом запуске не требуется.
- В настройках ключ скрыт; доступны действия «Показать», «Заменить» и «Удалить».
- Конкретный механизм хранения нужно выбрать отдельно для Windows, Linux и macOS при выборе стека. Общая цель согласована, платформенная реализация пока не выбрана.

Предварительный план выпуска — сначала Windows, позднее Linux и macOS. Это направление планирования, а не утверждённый график или гарантия одинаковых возможностей на всех ОС.

## Ошибка облачной обработки диктовки: принятое решение

Если локальное распознавание завершилось, а облачная редактура или структурирование завершились ошибкой:

- Сохранить распознанный текст и сразу скопировать его в системный буфер обмена.
- Показать в верхней панели ошибку и выбор: «Повторить обработку» или «Вставить без обработки».
- Пользователь может сразу вставить распознанный текст обычным сочетанием вставки (например, Ctrl+V), без повторного обращения к LLM и без нажатия кнопки в панели.
- Автоматической вставки в поле при этой ошибке нет; вставка выполняется по действию пользователя.
- Для этого сценария не восстанавливать прежнее содержимое буфера автоматически: распознанный текст должен оставаться доступным для ручной вставки. Это исключение из общего поведения восстановления буфера при обычной автовставке.

После успешного повтора облачной обработки диктовки сразу вставлять обработанный текст в исходное поле, без дополнительного предпросмотра или подтверждения. Поведение при недоступности исходного поля, ошибки копирования в буфер и закрытие панели предстоит уточнить отдельно.

Это правило относится к диктовке. Ответы ассистента и на вопросы по экрану показываются в верхней панели. Редактор выделения показывает предпросмотр и сразу копирует результат в буфер для применения через Ctrl+V или кнопку вставки. Готовый промпт сразу вставляется в исходное поле без предпросмотра.

## Нет ключа или модели: принятое решение

- При вызове облачной функции без ключа или назначенной модели показать конкретную причину: что именно не настроено.
- Из сообщения пользователь по клику переходит непосредственно к нужной настройке: полю ключа или выбору модели для соответствующей задачи.
- После перехода кратко визуально выделить нужный раздел или элемент, чтобы пользователь сразу увидел место исправления.
- После перехода нужный блок остаётся чётким, остальной интерфейс окна размывается и затемняется примерно на 400 мс. Сила блюра, затемнения и характер анимации уточняются на макетах.
- Локальная диктовка без обработки остаётся доступной.

## Точка продолжения

Поведение при неудачной вставке согласовано в [спецификации вставки](04-text-insertion.md): готовый текст копируется в буфер с сообщением для ручной вставки. В истории согласованы исходная расшифровка и итог обработки в одной записи. Продолжение — в [истории и служебных настройках](05-history-and-settings.md). Оставшиеся состояния подключения и ошибки каталога будут уточняться в подробной спецификации. Ошибки и повторные попытки в остальных функциях нужно обсуждать в контексте их результата, не распространяя на них автоматически правила диктовки.

Проверка доступа к каталогу не подтверждает работоспособность всех моделей и функций; состояния и ошибки предстоит уточнить.

Провайдера, общий ключ, отдельный выбор модели по задачам, автоматическую проверку при сохранении ключа и единый раздел «Модели» повторно не согласовывать: эти решения приняты.
