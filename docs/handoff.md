# Продолжение проекта с другого аккаунта

Состояние сохранено 16 октября 2026 года. Для продолжения не требуется история предыдущего чата: согласованные решения, открытые вопросы, исследование и оригинальные референсы находятся в этом репозитории.

## Где мы остановились

Идёт проектирование новой версии SpeakCursor. Последнее решение пользователя: **в первой версии из облачных провайдеров поддерживается только OpenAI**. Anthropic и сторонние OpenAI-совместимые сервисы отложены.

Следующий пункт обсуждения — **настройки ключа OpenAI и назначения моделей по функциям**. Тема для следующего предложения: достаточно ли одного общего ключа OpenAI либо нужны отдельные настройки. Ответ ещё не получен. Не выдавать предложенный вариант за согласованный и не повторять вопрос о выборе провайдера.

Основные сценарии локальной диктовки и обработки новой речи уже согласованы. Остальные функции включены в первоначальный объём, но их подробное поведение, UI и критерии приёмки ещё нужно обсудить.

## Как начать на другом аккаунте

1. Подключить GitHub с доступом к `VllSunday/speakcursor` и открыть сохранённую версию репозитория.
2. Прочитать [AGENTS.md](../AGENTS.md), [состав продукта](product-scope.md) и [оглавление документации](README.md).
3. Открыть [облачную обработку](features/03-cloud-processing.md) и продолжить с точки выше.
4. Для визуальной работы использовать [набор референсов](references/voiceos/README.md), а не загружать материалы заново.

Короткий запрос для нового чата:

> Продолжим проектирование SpeakCursor. Прочитай AGENTS.md, docs/handoff.md, docs/product-scope.md и спецификации в docs/features. Веди обсуждение по одному вопросу и записывай ответы. Мы остановились на настройке OpenAI и выборе моделей по функциям. Пока занимаемся требованиями и UX; стек и реализацию обсудим после макетов и спецификаций.

## Что пользователь хочет получить

Открытое минималистичное настольное приложение с собственными API-ключами и выбираемыми моделями. Целевые платформы — Windows, macOS и Linux; очередность поддержки и точная матрица возможностей по ОС ещё не выбраны. Лицензия открытого проекта также не выбрана.

Основное окно для настроек, нижняя панель записи, верхняя панель диалога/результатов и обводка экрана. Визуальный ориентир — VoiceOS. Состав экранов и финальные макеты ещё не утверждены.

## Подтверждённые решения

- Локальные модели только для распознавания речи, с CPU/GPU в пределах возможностей будущего бэкенда.
- Ручной выбор без мастера и рекомендаций; подключённые локальные модели хранятся списком с одной активной.
- Переход с GPU на CPU после ошибки — только с согласия пользователя.
- Выбранная модель загружается при старте приложения; время выгрузки в простое настраивается.
- После выгрузки запись начинается сразу, модель подготавливается параллельно; запись дожидается распознавания.
- Три режима новой диктовки: без обработки, редактура, структурирование.
- Общая клавиша диктовки использует выбранный режим; дополнительно можно назначать отдельные клавиши/комбинации режимам.
- Исходный режим — «Без обработки», без необходимости API-ключа.
- Диктовка вставляется в исходное поле. Ответ на вопрос показывается сверху, оформляется для чтения и доступен для копирования; автоматически в другое приложение не вставляется.
- Подготовка промптов — самостоятельная функция с отдельным вызовом; работает с речью без обязательного изображения.
- Нужны редактор выделения, вопросы по обведённой области экрана, словарь и стили, запись без удержания, ассистент с диалогом, поиском и голосовыми ответами.
- Модели API назначаются по задачам; после ввода ключа нужен каталог с фильтрацией по подтверждённым возможностям моделей.
- Почта, календари, заметки, другие облачные провайдеры и встроенные локальные LLM/vision остаются на будущее.

Подробности и ограничения: [состав продукта](product-scope.md) и [журнал решений](decisions.md).

## Порядок работы, выбранный пользователем

1. Список функций — первоначальный объём согласован.
2. Обсуждение сценариев и необходимых элементов интерфейса — текущий этап.
3. Визуальные макеты под функции.
4. Полные спецификации каждой функции с ошибками и критериями приёмки.
5. Выбор стека.
6. Реализация и тестирование по этапам.

Рабочие записи ведутся сразу по ходу разговора. Пользователь просит, чтобы агент сам предлагал следующий конкретный вопрос, а не повторял «продолжаем?» или «с чего начнём?». Принятые решения сохраняются до перехода к следующей теме.

## Готовность отдельных блоков

| Блок | Что уже согласовано | Что предстоит |
| --- | --- | --- |
| Локальная диктовка | Основной жизненный цикл и выбор модели | Точные элементы UI, каталог скачивания, форматы модели, ошибки, GPU по ОС |
| Обработка речи | Режимы, клавиши, исходный режим, автовставка | Степень редактуры, названия и UI, обработка ошибок |
| OpenAI | Провайдер, свой ключ, модели по задачам | Настройки ключей, проверка, каталог, хранение, ошибки |
| Вставка и история | Сохранить существующие возможности | Поведение по ОС, развитие истории, детали настроек |
| Редактор выделения | Сокращение, перевод, тон, структура | Предпросмотр или применение, действия и отмена |
| Помощь по экрану | Указание/обводка и вопрос | Границы захвата, вложения, состояния и разрешения |
| Подготовка промпта | Отдельный режим, речь и необязательные изображения | Результат, вставка/копирование, уточнения и правила |
| Стили и словарь | Нужны; сочетания для стилей | Набор, редактирование и связь с режимами |
| Ассистент | Диалог, поиск, текст и голос | История контекста, поиск, TTS и действия панели |
| Восстановление | Желательно, если несложно | Минимальный объём и покрываемые сбои |

## Существующая реализация

Исходный базовый коммит приложения: `94664e532a938aa283bf1801389fe7a44fb244da`. Это Python-приложение для Windows с PySide6, faster-whisper, sounddevice, keyboard, pyperclip и необязательным OpenAI. Есть F8/Shift+F8, настройки трея, история 20 текстов, вставка, автозапуск и выгрузка модели.

Текущий стек существующего кода **не выбран автоматически как стек новой версии**. В течение проектирования изменялись документы и собирались референсы; новые функции приложения ещё не реализованы.
