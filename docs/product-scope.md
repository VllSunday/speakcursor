# Состав продукта

Статус: первоначальный состав функций согласован; Rust выбран языком новой версии. Библиотека интерфейса, детали поведения и реализация ещё не утверждены.

## Согласованные рамки

- Полноценное открытое настольное приложение с минималистичным интерфейсом.
- Приложение должно быть максимально легковесным. Для новой версии выбран Rust вместо Python/PySide6; минимизация потребления ресурсов учитывается при выборе библиотеки интерфейса и остальных компонентов. Конкретные лимиты ещё не заданы.
- Автозапуск включён по умолчанию, пользователь может отключить его переключателем в настройках.
- Закрытие основного окна крестиком скрывает его; приложение остаётся в трее, горячие клавиши работают. Полный выход — через пункт «Выйти» в меню трея.
- Основное окно для настроек и управления возможностями; плавающие панели для работы поверх других приложений.
- Пользователь вводит один собственный API-ключ OpenAI для всех облачных функций и отдельно выбирает модель для каждой задачи.
- Диктовка и команды к выделению вызываются раздельно: диктовка вставляет произнесённый текст или заменяет выделение; в режиме редактирования или анализа речь задаёт инструкцию к тексту. Наличие выделения не переключает диктовку в команды. Верхний чат вызывается отдельно и автоматически подхватывает выделение как контекст. Дополнительные сочетания для стилей необязательны; группировка редактирования и анализа и конкретные клавиши ещё не выбраны.
- Настройка максимально простая и ручная: без мастера первого запуска и автоматических рекомендаций моделей. Пользователь самостоятельно выбирает нужное подключение или локальную модель.
- Локальная модель подключается через системный диалог выбора. Конкретный тип выбора — файл или папка модели — зависит от формата и будущего бэкенда; поддержка произвольного формата не согласована.
- Для локальной диктовки сохраняется список добавленных моделей с выбором одной активной. Повторно искать модель в файловой системе при переключении не требуется.
- Локальные модели в первой версии используются только для распознавания речи.
- Локальная диктовка должна поддерживать CPU и доступное GPU-ускорение. Конкретные бэкенды и поддержка ускорения по ОС будут определены при выборе стека.
- Если запуск выбранной модели на GPU не удался, переход на CPU допускается только после явного согласия пользователя; автоматического переключения без подтверждения нет.
- Выбранная локальная модель загружается при запуске приложения. Время простоя до её выгрузки из памяти настраивается пользователем.
- После выгрузки модели запись следующей диктовки начинается сразу, модель подготавливается параллельно. Завершённая запись дожидается готовности модели для распознавания; повторять речь не нужно.
- Редактура, анализ изображений, подготовка промптов и ассистент работают через API. Встроенный запуск локальных LLM и локальных моделей анализа изображений отложен.
- Цель — кроссплатформенность: Windows, macOS и Linux. Предварительный план — первый выпуск для Windows, позднее сборки для Linux и macOS. Это пока планы; окончательная очередность, сроки и матрица возможностей по ОС не утверждены.
- Визуальный ориентир — VoiceOS; поведение проектируется под собственный состав функций.

Отказ от помощника первоначальной настройки не отменяет согласованную функцию ИИ-ассистента: это отдельный рабочий режим приложения.

| 6 | Редактор выделения | Сокращение, перевод, тон и структура существующего текста |

| 9 | Управление записью | Обычная диктовка: первое нажатие сочетания начинает запись, второе завершает, Esc отменяет без распознавания и вставки |

| 11 | Ассистент | Вопросы, продолжение диалога, поиск в интернете, текстовые ответы в верхней панели и автоматическое озвучивание при включённом переключателе в настройках |

Точные сочетания клавиш, значения по умолчанию и варианты просмотра/применения результата ещё нужно согласовать.

Для успешной новой диктовки согласована немедленная вставка готового текста в исходное поле во всех четырёх вариантах обработки, с сохранением истории. Ответы на вопросы показываются в верхней панели, аккуратно оформляются и доступны для копирования; в другие приложения автоматически не вставляются. Результат редактирования выделения показывается в предпросмотре и сразу копируется в буфер; пользователь применяет его через Ctrl+V или кнопку вставки. Результат можно уточнять голосом или текстом в том же диалоге без повторного выделения. Готовый промпт сразу вставляется в исходное поле без предпросмотра.

Пользователь может пользоваться одной общей клавишей диктовки с выбранным режимом по умолчанию; назначать отдельные сочетания для всех режимов необязательно. До пользовательской настройки используется «Без обработки», без дополнительной LLM-редактуры и без требования API-ключа.

При ошибке облачного исправления, структурирования или пользовательского стиля распознанный текст сразу копируется в системный буфер. Верхняя панель показывает выбор «Повторить обработку» или «Вставить без обработки»; пользователь также может сразу вставить текст через Ctrl+V. Автовставки при ошибке нет. Прежний буфер автоматически не восстанавливается, чтобы сохранить возможность ручной вставки. После успешного повтора облачной обработки диктовки результат сразу вставляется в исходное поле без дополнительного предпросмотра или подтверждения.

Если исходное окно закрыто или вставка не удалась, готовый текст копируется в буфер, а верхняя панель автоматически и плавно открывается с сообщением «Не удалось вставить текст — он скопирован» и примерно через пару секунд закрывается. Текст остаётся доступным для ручной вставки, прежний буфер автоматически не восстанавливается. Подробности: [вставка текста](features/04-text-insertion.md).

В истории диктовки сохраняются два варианта текста в одной записи: исходная расшифровка и итог после LLM-обработки. Без дополнительной обработки достаточно одного текста. По умолчанию история хранится 30 дней; доступны «Не удалять автоматически» и полная очистка. Произвольный срок пока не предусматривается. Выборочное удаление отдельных записей пока отложено. При ошибке первоначальной LLM-обработки можно повторить её из истории по исходной расшифровке без новой диктовки. Успешный результат такого повтора показывается в той же записи; исходная расшифровка сохраняется. Согласован обычный текстовый поиск по исходной расшифровке и результату обработки без расширенных возможностей. Совпадения показываются простым списком: исходная расшифровка слева, обработанный итог справа, рядом с каждым вариантом своя иконка копирования. При длинном тексте можно показывать фрагмент, но копировать полный выбранный вариант. Подробности — в [истории и служебных настройках](features/05-history-and-settings.md).

## Подключения и модели

Согласованы один общий API-ключ OpenAI для всех облачных функций и отдельный выбор модели для каждой задачи. Отдельные ключи по функциям в первой версии не нужны. Пользователь должен видеть доступные модели подключения. Назначения собраны в едином разделе «Модели»: список задач и выбор подходящей модели напротив каждой.

Ключ сохраняется между запусками в защищённом хранилище ОС. В настройках он скрыт; доступны действия «Показать», «Заменить» и «Удалить». Конкретные механизмы для Windows, Linux и macOS будут выбраны при выборе стека.

Если облачная функция вызвана без ключа или назначенной модели, сообщение объясняет причину и позволяет по клику перейти к нужной настройке. После перехода нужный блок остаётся чётким, остальной интерфейс окна размывается и затемняется примерно на 400 мс. Локальная диктовка без обработки остаётся доступной.

### Согласованный сценарий выбора API-моделей

1. Пользователь указывает общий API-ключ OpenAI.
2. При сохранении ключа приложение автоматически проверяет подключение OpenAI и загружает каталог доступных моделей; отдельное нажатие кнопки проверки не требуется.
3. Для каждой функции пользователь видит модели, подходящие для её типа задачи: текст, изображения или аудио.
4. Пользователь вручную назначает модель функции. Одна и та же совместимая модель может использоваться несколькими функциями; обязательного выбора единственной общей модели нет.

Каталог обновляется при открытии раздела «Модели» и по кнопке «Обновить список». Назначенные пользователем модели сохраняются при обновлении.

Для текстовой редактуры, редактирования выделения и подготовки промптов нужны текстовые возможности; для помощи по экрану — входные изображения; для голосового ответа — синтез речи. Упоминание пользователем категории «аудио» не означает согласование облачного распознавания вместо локальной диктовки. Обработка видео не включалась: пользователь поправил это слово на изображения.

Для первой версии пользователь выбрал **только OpenAI**. Anthropic и сторонние OpenAI-совместимые сервисы отложены. Ранее обсуждавшийся универсальный совместимый API не является требованием первого выпуска.

Уточнения, которые нужно учитывать при дальнейшем проектировании:

- Для возможных будущих провайдеров совместимость определяется интерфейсом сервиса, а не форматом API-ключа. В первой версии подключается только OpenAI.
- Для обработки экрана нужна поддержка изображений, для голосовых ответов — синтез речи.
- Поиск в интернете требует поискового инструмента или поддержки со стороны сервиса; произвольная текстовая модель сама этого не гарантирует.
- Сценарий каталога с фильтрацией по задаче согласован. Технический способ получения каталога, ручной ввод при отсутствии каталога и отображение несовместимых моделей ещё не определены.
- Перечень моделей, предоставляемый API, не всегда содержит сведения об их входных/выходных форматах. Фильтрация должна опираться на подтверждённые возможности сервиса/модели; при отсутствии таких сведений приложение не должно выдавать догадку за совместимость.

## Желательная возможность

Восстановление после ошибки — желательно, если базовый вариант не потребует значительного усложнения. Что именно сохраняется и какие сбои покрываются, пока не определено.

## Отложено

- Anthropic и другие облачные провайдеры, включая сторонние OpenAI-совместимые сервисы.
- Действия с почтой, календарями и заметками. При архитектурном проектировании предусмотреть возможность расширения, без реализации интеграций в первой версии.
- Встроенные локальные языковые модели и локальный анализ изображений.

## Согласованные поверхности интерфейса

- Основное окно: API-ключи и подключения, выбор моделей, настройки и управление функциями.
- Нижняя панель: компактная плашка диктовки с волнами, отражающими речь, и состоянием записи.
- Верхняя панель: вызываемый сочетанием минималистичный чат для быстрого вопроса, диалога или поиска, с одним полем ввода и кнопкой «Отправить», раскрываемый для просмотра истории переписки; диалог, ответы и подготовленный текст, выбор вариантов, просмотр, копирование, подтверждение и отмена действий. Ответы оформляются для удобного чтения с абзацами и отступами и показываются постепенно по мере генерации, с быстрой плавной анимацией без искусственного замедления; без автоматической вставки в другие приложения.
- Поверхность указания на экране: след курсора/обводка для задания визуального контекста.

Краткие ошибки приложения показываются в той же верхней панели: она плавно появляется и примерно через пару секунд закрывается. Ошибки, требующие действия, сохраняют ранее согласованные кнопки и переходы. Конкретные цвета, размеры, фокус, несколько мониторов и поведение по ОС ещё предстоит определить.

## Границы текущего этапа

Базовые пользовательские сценарии согласованы. Краткая [сводка первой версии](mvp.md) служит основой для выбора стека и первого этапа реализации; детали ниже остаются историей проектирования.

Обсуждение возобновлено. Согласованы один общий ключ OpenAI и отдельный выбор модели для каждой задачи. Проверка подключения и загрузка каталога при сохранении ключа выполняются автоматически. Согласован единый раздел «Модели» для назначения моделей задачам. Согласована автовставка диктовки после успешного повтора. Согласовано хранение ключа между запусками в защищённом хранилище ОС. Согласованы конкретная причина ошибки, переход к настройке и краткое выделение нужного места при отсутствии ключа или модели. Для выделения выбран блюр с затемнением остального интерфейса примерно на 400 мс. Согласовано обновление каталога при открытии раздела «Модели» и по кнопке с сохранением назначений. Согласовано копирование готового текста в буфер с уведомлением при неудачной вставке. В пункте 5 согласовано сохранение исходной расшифровки и итога обработки в одной записи истории. Согласованы 30 дней хранения по умолчанию, отключение автоудаления и полная очистка. Согласован повтор из истории после ошибки первоначальной LLM-обработки. Результат повтора показывается в той же записи. Выборочное удаление отдельных записей пока отложено. Согласован обычный текстовый поиск по обоим вариантам текста. Автозапуск включён по умолчанию и отключается в настройках. Крестик скрывает окно с продолжением работы в трее, полный выход отдельным пунктом. В пункте 6 согласованы предпросмотр, копирование результата в буфер и применение через Ctrl+V или кнопку вставки. Согласованы голосовые и текстовые команды с одинаковой обработкой через минималистичный чат в верхней панели, раскрываемый для просмотра переписки. Согласовано потоковое отображение ответов с быстрой плавной анимацией. Диктовка и команды к выделению вызываются раздельно. Диктовка может заменять выделение новым текстом. Повторно уточнены общий вызов диктовки с выбираемым режимом по умолчанию, необязательные сочетания режимов/стилей и отдельный вызов подготовки промпта. Готовый промпт сразу вставляется без предпросмотра. Уточнение результата редактора в том же диалоге без повторного выделения согласовано. Далее — границы снимка для помощи по экрану. Остальные вопросы редактора остаются открытыми. Оставшиеся состояния подключения и каталога уточняются в подробной спецификации.
